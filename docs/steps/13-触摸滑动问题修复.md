# 步骤 13：触摸只能点不能滑 —— 根因与修复（fodbridge v6）

## 根因

为了指纹采图，桥接需要让触摸 HAL（`vendor.xiaomi.hw.touchfeature-service` 里的 THP）进入
`support fod = 1`（`setModeValue(0,10,1)`），THP 才会在手指按到指纹区时写 `fod_press_status`。

v3/v4 为了"每次都能采图"，把这个标志**常驻打开**（每 1 秒补一次，抬手后立刻补）。
副作用：THP 在 FOD 模式下会把手势/滑动当成"指纹按压"处理，**移动事件被吞** →
系统表现就是"只能点击、不能滑动"。

## 修复（v6，已部署）

桥接改成**按锁屏状态动态开关**：

```sh
locked() { dumpsys trust | grep -o 'deviceLocked=[01]'; }   # 0.01s，很便宜

state loop（每 1 秒）：
  deviceLocked=1（锁屏/熄屏） → support fod = 1 + extCmd(1,1) 触摸控制
  deviceLocked=0（已解锁）    → support fod = 0
```

- 解锁后 ≤1 秒自动退出 FOD 模式 → 滑动恢复正常
- 触摸处理也只锁屏时发 `extCmd(4)`；解锁后桥接完全不碰 HAL
- 熄屏触摸「唤醒 + 重新触发采图」的逻辑保留（仅锁屏时生效）

状态文件：`/data/local/tmp/fod.locked`（1=锁屏，0=已解锁）
日志：`/data/local/tmp/fodbridge.log`

## 验证方式

```
adb shell su -c "cat /data/local/tmp/fod.locked"
# 解锁后应为 0，锁屏时应为 1
adb shell su -c "logcat -d -s THP-DAE | grep 'support fod' | tail -5"
# 解锁后应为 support fod:0
```

## 如果还有问题

- 锁屏界面上滑（呼出密码盘）如果也被影响：可以进一步把 support fod 限制成
  "只在熄屏(AOD) 时开启"，锁屏亮屏时用 `extCmd(4)` 直接触发（会牺牲一点解锁成功率）
- 完全停用桥接：`adb shell su -c "pkill -f fodbridge.sh"`（重启后模块会再拉起）
