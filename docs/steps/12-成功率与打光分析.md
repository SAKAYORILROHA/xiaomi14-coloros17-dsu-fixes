# 步骤 12：解锁成功率 / 打光触发率分析

## 实测数据（03:16 ~ 03:22 的日志）

桥接记录的按压（都在指纹区内）：

```
03:16:21.665 press x=62420 y=242430
03:16:22.597 press x=63430 y=244230   ← 采图
03:16:24.271 press x=64450 y=243650
03:16:25.012 press x=61910 y=238450
03:16:25.689 press x=64300 y=241450   ← 采图
03:16:26.959 press x=64700 y=239570
...
03:17:12.671 press x=65370 y=241190   ← 采图（解锁成功）
```

HAL 采图 3 次，按压约 20 次 → **采图率约 15%**；采图间隔 ~3s。

算法结果：

```
03:16:22  image_quality=25  match_score=58  → NotMatched
03:16:25  image_quality=20  match_score=56  → NotMatched
03:17:12  image_quality=25  match_score=57  → notifyAuthSuccess（valid_area=100, key_point_num=380）
```

认证会话本身一直活着（requestId 66 期间两次 NotMatched 都没结束），所以不是"没会话"。

## 结论

1. **打光/采图不是按区域触发的**：按压都在 (600~650, 2380~2440) 内，成功与失败的点分布无规律
2. 真正原因是 **HAL 的采图重试节流**：一次采图/比对失败后，HAL 会等约 2~3 秒才接受下一次采图，
   这期间的按压不会打光（所以主观上像"只有某些角度/区域才亮"）
3. **识别率低的根因是画质**：`image_quality` 只有 20~25，`match_score` 56~58 正好卡在阈值附近，
   同一枚手指一半成功一半失败
4. 画质低的直接原因：ColorOS 的指纹"压暗遮罩 + 局部高亮"链路在本机不工作：
   - `OnScreenHighLightControl-->hbmControl exception : java.util.NoSuchElementException`
   - `OnScreenHighLightControl-->isDisplayFodColorSupport ---, feature = null`（OPlus 面板 feature HAL 缺失）
   - `OnScreenFingerprintDimLayer` 被 OPlus SurfaceFlinger 置为不可见/空裁剪（前面步骤 09 已确认）
   → 采图时屏幕没有压暗，环境光把指纹图像的对比度拉低

## 本次调整（fodbridge v5）

把桥接的指纹矩形从 480x520px 收紧到实际传感器范围（±10px）：

```
X1=48100 X2=71900 Y1=227200 Y2=251000   (px 481~719, 2272~2510)
```

避免在传感器外也发 `extCmd(4)` 造成无效采图/打光。

## 使用建议（能立刻提升成功率）

1. 每次按压后**等 2~3 秒**再按下一 次（HAL 重试节流），按住约 1 秒再抬起
2. 指腹**平贴**、覆盖整个传感器区域（屏幕底部正中 1.2~1.7cm），不要用指尖
3. **同一根手指多录 1~2 枚**（设置 → 指纹 → 添加指纹），每枚都是独立模板，HAL 取最佳匹配，成功率会明显上升
4. 擦干净屏幕/膜上的油污
