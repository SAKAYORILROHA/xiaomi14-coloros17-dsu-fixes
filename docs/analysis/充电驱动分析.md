# 小米快充 90W：内核层绕过电池认证（结论：不可行）

> 设备：Xiaomi 14（houji，SM8650），HyperOS 4（OS4.0.0.12.XNCCNXM）
> 内核：`6.1.138-android14-11-g0c3559bcd85-ab14529422`
> 输入镜像：`F:\boot.img`

---

## 一、结论先行

1. **`F:\boot.img` 里没有任何充电驱动**（搜索 `battery_psy_set_fcc` / `BattAuth` / `battery_chg` / `fg_update_status` 全部 0 命中）
2. 充电驱动是模块：`/vendor_dlkm/lib/modules/qti_battery_charger.ko`（381,840 字节）
3. 但**改这个 .ko 也没用**：AP 侧已经在写 `FCC = 50000000`（50A，等于不限），实际电流仍被压在 2A —— 限制在 AP 之下的 **ADSP/PMIC 固件**里
4. `fcc: BattAuth-2000` 这行日志是 **ADSP 固件自己打印**的（内核用 `"[ADSP] %s"` 转发），不是 AP 侧算的
5. 所以"内核层绕过电池认证"在本机不成立；可行的是换原装电池，或继续用 ColorOS 侧充电

## 三、qti_battery_charger.ko 逆向结果

### 3.1 基本信息

```
vermagic   6.1.68-android14-11-maybe-dirty SMP preempt mod_unload modversions aarch64
license    GPL v2
depends    miev, pmic_glink, panel_event_notifier
模块签名   CONFIG_MODULE_SIG_FORCE 未开启 → 改过的 .ko 可以 insmod（只会 taint）
```

### 3.2 关键函数

| 符号 | 偏移 | 大小 | 作用 |
|---|---|---|---|
| `battery_chg_callback` | 0x29e8 | 4760 | glink 消息回调（打印/转发） |
| `battery_psy_set_prop` | 0x5320 | 744 | power_supply 属性读写，含 "Kernel Set FCC to %u" |
| `battery_psy_set_charge_current` | 0x5630 | 372 | 组装 glink 消息下发电流 |
| `xm_charger_debug_info_print_work` | 0x1c44 | 1176 | 打印 chg_type/vbus/ibus |

### 3.3 下发逻辑（反汇编还原）

```
battery_psy_set_charge_current:
  ldr  w8, [x0, #0x29c]     ; 上限
  cmp  w8, w20              ; 上限 vs 请求值
  b.lt err                  ; 请求 > 上限 → -EINVAL
  组装 glink 消息 (0x1_0000_800a)
  bl   <发送>
  str  w20, [x21, #0x290]   ; 记录生效值
```

### 3.4 决定性证据

```
$ dmesg | grep set_fcc
[1836] BATTERY_CHG: battery_psy_set_fcc: Kernel Set FCC to 6000000    ← 我们写的，生效
[1837] BATTERY_CHG: battery_psy_set_fcc: Kernel Set FCC to 50000000   ← 内核自己写 50A
[1838] BATTERY_CHG: battery_psy_set_fcc: Kernel Set FCC to 50000000

$ cat /sys/class/power_supply/battery/constant_charge_current
2000000                                                               ← 实际仍是 2A

$ dmesg | grep -E 'ADSP|BattAuth'
handle_message: [ADSP] fg_update_status:: ... fcc: BattAuth-2000 ...   ← ADSP 固件算的
```

AP 侧已经"全开"，限制在 ADSP/PMIC 固件 → **改内核或改 .ko 都不会让电流上去**。

## 四、用户态/内核态尝试记录（全部无效或已回滚）

| 尝试 | 结果 | 已回滚 |
|---|---|---|
| `echo 1 > /sys/class/qcom-battery/authentic` | FCC 不变，`constant_charge_current` 被置 0 | ✅ 已还原 0 |
| `echo 1 > remove_temp_limit` | `btemp` 跳到 50℃，`fcc: ChargingSus-0` 充电挂起 | ✅ 已还原 0 |
| `echo 0 > restrict_chg / charge_control_en` | 无变化 | ✅ |
| `echo 6000000 > constant_charge_current` | 1 秒内被内核覆盖回 2A | ✅ |
| `setprop ctl.stop micharge-hal` + 写 6A | 仍被内核覆盖（是内核在写，不是 HAL） | ✅ 已重启 |
| KPM 模块 | `ksud kpm version` → `Inappropriate ioctl for device`，内核无 KPM loader | — |
| 自编译 .ko | 需要内核源码 + clang 17；且 AP 侧已 50A，无意义 | — |

## 五、真正可行的方案

| 方案 | 可行性 | 说明 |
|---|---|---|
| 换原装电池 | 高 | 认证芯片匹配后 FCC 放开；现电池 `cycle_count=1`、`4015/4610mAh` 疑为换过 |
| 用 ColorOS 侧充电 | 高 | 移植版不跑小米 BattAuth，实测能到 90W |
| 改 ADSP/PMIC 固件 | 极低 | 固件签名校验，改错直接不能充电 |
| 改 boot.img 内核 | 无意义 | 充电代码不在内核里 |

## 六、已保留的有效成果

```
persist.vendor.batteryantiaging         0      （原 2）
persist.vendor.battery.health.optimise  false  （原 true）
persist.vendor.night.charge             0      （原 1）
```

效果：插 90W 时输入从 `SDP 0.5A` → `PD_PPS 6A`，电池电流 0.45A → **2.09A（约 9W）**，已到电池 FCC 上限。
