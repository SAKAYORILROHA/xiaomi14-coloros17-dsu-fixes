# 小米快充 90W：内核层绕过电池认证（方案评估）

> 设备：Xiaomi 14（houji，SM8650），HyperOS 4（OS4.0.0.12.XNCCNXM）
> 内核：`6.1.138-android14-11-g0c3559bcd85-ab14529422`（clang 17.0.2 / LLD 17.0.2）
> 结论：**KPM 这条路在本机内核上不可用**，但内核允许加载自编译 .ko

---

## 一、卡在哪（实测证据）

```
# 90W 充电器插着时
fg_update_status:: ... fcc: BattAuth-2000, icl: chg_det-6000
                        ↑ 电池侧 FCC=2A      ↑ 输入侧已给 6A

battery_psy_set_fcc: Kernel Set FCC to 50000000     # 内核每轮写 50A（=不限）
```

- 输入侧（PD PPS 6A）已经放开 → 充电器没问题
- 电池侧 FCC 被 ADSP 电量计固件按"电池认证结果"算成 **2000mA**
- 内核驱动每秒用 ADSP 报的 fcc 重新写一次充电电流 → 用户态 `echo 6000000 > constant_charge_current` 会被 1 秒内覆盖
- 停掉 `micharge-hal` 也一样被覆盖（是内核在写，不是 HAL）

所以限制点在**内核读 FG 状态的逻辑 + ADSP 固件**，两者都不在用户态可控范围。

## 二、KPM 是否可用：不可用

```
$ ksud kpm version
Error: Inappropriate ioctl for device (os error 25)

$ ls /dev/kpm
（不存在）

$ dmesg | grep -i kpm
（无输出）

$ grep ' kp_' /proc/kallsyms
0000000000000000 d kp_kallsyms_lookup_name
0000000000000000 d kp_binder_proc_transaction
0000000000000000 d kp_msm_update [sched_penalty]
```

- 只有 3 个 `kp_*` 符号，没有 KPM loader
- 内核 config 里没有 KPM/KPATCH 选项
- `ksud kpm` 命令本身存在（SukiSU 4.1.3 自带），但 ioctl 返回 ENOTTY → 内核没实现

**要用 KPM，必须刷一个用 KernelPatch 编译过的内核**（KernelPatch 会加 KPM loader + `kp_*` API），本机原生内核没有。

## 三、还有一条路：直接加载自编译内核模块

```
$ cat /proc/sys/kernel/modules_disabled
0
$ which insmod
/system/bin/insmod
```

内核允许 `insmod`，所以可以编译一个 `.ko` 去 hook。

### 需要准备的环境

| 项 | 要求 |
|---|---|
| 内核源码 | `github.com/MiCode/Xiaomi_Kernel_OpenSource`，分支/标签对应 `6.1.138`（houji） |
| 工具链 | clang 17（Android LLVM `r487747c`）+ LLD 17 |
| 匹配 vermagic | `insmod` 会校验 `6.1.138-android14-11-g0c3559bcd85-ab14529422 SMP preempt`；用同名源码 tag 编译才能一致，否则要 `insmod --force`（有崩溃风险） |
| 加载方式 | `insmod xm_charge_sc.ko`，或打包成 KernelSU 模块在 post-fs-data 里加载 |

### hook 点与伪代码

目标：把 ADSP 报上来的 `fcc`（2000mA）在内核侧替换成目标值，或者让 `battery_psy_set_fcc()` 不按 FG 值写。

```c
// 方案 1：hook 充电驱动的 FCC 写入函数
static void (*orig_set_fcc)(struct power_supply *psy, int fcc);
static void my_set_fcc(struct power_supply *psy, int fcc)
{
    // 电池认证失败时 ADSP 会给 2000mA，这里直接改成目标值
    if (fcc <= 2000000)
        fcc = XM_FCC_TARGET;      // 例如 9000000（9A）
    orig_set_fcc(psy, fcc);
}

// 方案 2：hook FG 状态处理里填 fcc 的地方
// qti_battery_charger 解析 ADSP 的 fg_update_status 后调用
// power_supply_changed / batt_set_fcc，将 status->fcc 替换

// 注册
kp_hook(kp_kallsyms_lookup_name("battery_psy_set_fcc"), my_set_fcc, &orig_set_fcc);
```

> `battery_psy_set_fcc` 是内核日志里打 `Kernel Set FCC to ...` 的函数，可以在源码里搜这行日志定位。
> 注意 Android 默认隐藏 kallsyms 地址：`echo 0 > /proc/sys/kernel/kptr_restrict` 后可读。

### 风险

- FCC 提到 9A 属于超出电池认证策略，**有鼓包/发热风险**，务必保留温控
- 内核模块写错 = 直接 kernel panic（充电时重启）
- 90W 需要**充电泵（bq2597x）**工作：现在 `cp_mode=0`、`bus_voltage=4700`（5V），说明充电泵没进 CP 模式；光提 FCC 不一定能到 90W，还要保证 CP 模式拉起

## 四、更省事的两条替代

1. **换原装电池**：认证通过后 FCC 会恢复到 4015mAh 对应值，90W 才有完整可能
2. **用 ColorOS 那边的快充**：ColorOS 移植版不跑小米电池认证，实测同样条件能上 90W（这也是你观察到的现象）

## 五、本次已保留的成果

```
persist.vendor.batteryantiaging        0     （原 2）
persist.vendor.battery.health.optimise false （原 true）
persist.vendor.night.charge            0     （原 1）
```

效果：输入从 `SDP 0.5A` → `PD_PPS 6A`，电池电流 0.45A → **2.09A**（约 9W），已到电池 FCC 上限。
